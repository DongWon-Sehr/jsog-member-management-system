# 주삼오공 (운동인증방) 관리 시스템 기능 명세서 (v1.1.0)

## 1. 개요
- **목적**: 온라인 운동인증 모임 회원 및 인증현황 관리, 카카오 챗봇 연동 자동화
- **플랫폼**: Google Workspace (Google Sheets + Google Apps Script).
- **접근 권한**: 관리자 (Google 계정 기반 인증 예정)

## 2. 기술 스택
- **FE**: Vue.js 3 (Composition API), Tailwind CSS, Phosphor Icons, **IMask**, **Chart.js**.
- **BE**: Google Apps Script (GAS) - **Controller-Service 아키텍처**.
    - **패키지 구조**: `main` (운영 코드), `tests` (검증 코드) 분리.
    - **인증**: 카카오 고유 ID 연동 및 이메일 스마트 매칭.
- **DB**: Google Sheets (Schema 기반 타입 관리).

## 3. 아키텍쳐 & 디자인 시스템

### 3.1. 프론트엔드 (Admin WebApp)
- **SPA (Single Page Application)**: 매끄러운 탭 전환 및 전역 상태 관리(`useStore`).
- **데이터 캐싱**: 탭 진입 시 불필요한 서버 호출을 차단하고 초기 1회 로드로 최적화.
- **인디고(Indigo) 디자인**: 통일된 테마와 반응형 레이아웃(Desktop/Mobile).
- **반응형 스티키 헤더**: 모바일 GNB 높이 증가에 대응하여 페이지 스티키 헤더의 오프셋을 반응형으로 조절(`top-28 md:top-16`).
- **모달 반응형 목록**: 모바일 환경에서 입력란이 좁아지는 문제를 방지하기 위해, 모달 내 테이블 목록을 모바일 전용 세로 카드형으로 배치하고 데스크톱에서는 가로 테이블 행으로 복원하는 하이브리드 구조 적용.
- **사용성 보강**: 모달 활성화 시 부모 창 스크롤 차단 및 위치 보존 로직 적용.
- **Optimistic UI (낙관적 UI 업데이트)**: 느린 GAS 응답 문제를 개선하기 위해 회원 등록/수정, 리워드 등록/삭제, 운동 로그 일괄 저장 시 전역 메모리 객체(`members`, `rewards`, `workoutLogs`, `workoutRecords`)를 즉시 선반영하여 대기 없이 UI를 갱신합니다. 서버 API가 최종 실패할 경우 이전 백업본 데이터로 자동 롤백 및 알림을 발생시킵니다.
- **저장 즉시 닫힘 및 닫기 상시 활성화**: 모든 모달은 저장 요청과 동시에 즉각적으로 닫히며, 백그라운드에서 API 통신이 진행됩니다. 닫기 버튼 및 ESC 키는 저장 진행 중에도 항상 활성화 상태를 유지합니다.
- **새 행 하이라이트 애니메이션**: 새로 추가된 데이터 객체(신규 회원, 리워드)는 추가와 동시에 옅은 노란색으로 강조 깜빡임(Pulse) 효과를 보인 후, 2초에 걸쳐 투명하게 자연 소멸되도록 하였습니다.
- **버전 표기 자동화**: 헤더 우측의 버전은 빌드 시 `package.json`의 `version`을 주입(`vite.config.js`의 `__APP_VERSION__`)하여 표시합니다. 과거 하드코딩 방식에서는 실제 버전과 화면 표기가 어긋나 있었습니다.
- **주차 선택 양방향 공유 (`selectedWeekId`)**: 대시보드와 운동 기록 탭은 하나의 주차 선택 상태를 공유합니다. 이전에는 대시보드의 '인증 카드 클릭' 경로에서만 값을 넘기고 운동 기록 탭이 읽는 즉시 비우는 **일회성 핸드오프**였기 때문에, GNB 탭으로 이동하면 선택이 유지되지 않고 역방향(운동 기록 → 대시보드)은 아예 동작하지 않았습니다. 이제 스토어의 값을 두 뷰가 직접 읽고 씁니다.
    - 운동 기록 탭은 진입 시 공유 주차가 다른 연도면 **연도 선택기를 그 연도로 먼저 맞춥니다.** 주차 목록이 연도로 필터링되어 있어 그렇지 않으면 선택이 유지되지 못합니다.
    - 뷰는 탭 전환마다 재마운트되므로(`keep-alive` 미사용), 각 뷰의 초기화 로직은 **유효한 선택이 없을 때만** 오늘 주차를 기본값으로 잡습니다. 대시보드 `onMounted`가 무조건 덮어쓰고 있어 넘어온 선택이 즉시 사라지던 문제를 함께 수정했습니다.
- **회원 정렬 기준 통일 (`sortedMembers`)**: 회원 목록과 운동 기록 목록은 시트 행 순서를 그대로 따르고 있어 시트에서 행이 이동하면 순서가 흔들렸습니다(v1.1.0 이전). 이제 스토어에서 `joined_at` 오름차순(빈 값은 `created_at` 폴백, 둘 다 없으면 맨 뒤, 동일 날짜는 이름 가나다순)으로 한 번 정렬한 `sortedMembers`를 만들고 `activeMembers`가 이를 파생하므로, 이를 참조하는 모든 화면이 같은 순서를 공유합니다.
- **CSV 내보내기 공통화 (`useCsv`)**: 뷰마다 중복 구현되어 있던 CSV 생성을 `composables/useCsv.js`로 통합했습니다. 모든 셀을 따옴표로 감싸고 값 안의 `"`는 `""`로 이스케이프하며(RFC4180) 줄 구분자는 `\r\n`을 사용합니다. 과거에는 컬럼 밀림을 막기 위해 메모·상세내용의 콤마를 공백으로 치환했는데, 이는 내보내는 데이터 자체를 변형시키는 문제가 있었습니다. 이제 콤마와 줄바꿈이 원본 그대로 보존됩니다.
- **로딩 오버레이**: 카드 크기를 `320×232px`로 고정하고 문구 영역에 2줄 높이(`44px`)를 확보해, 문구가 순환해도 박스 크기가 변하지 않습니다. 회전 스피너와 사람 아이콘을 제거하고 운동 이모지 8종(🏃 🏋️ 🧘 🚴 🏊 🤸 🎾 ⚽)이 1.4초마다 순서대로 교체됩니다. 교체는 `mode="out-in"` 없이 진입/이탈 트랜지션을 동시에 실행하여, 새 이모지가 왼쪽에서 들어오는 동안 기존 이모지가 오른쪽으로 빠져나가는 인수인계 형태입니다.
- **⚠️ 배포본 CSS 파이프라인**: `post-build.js`가 `index.html`을 자체 템플릿으로 재작성하면서 **Vite가 생성한 CSS 번들을 폐기**하고, Tailwind는 Play CDN(`cdn.tailwindcss.com`)에서 런타임에 클래스를 생성합니다. 결과적으로 **`App.vue`의 `<style>` 블록은 배포본에 포함되지 않습니다**(`.slide-up-*` 등 기존 트랜지션 CSS도 실제로는 적용되지 않고 있었습니다). 또한 앱 시작 직후 잠깐 떴다 사라지는 로딩 오버레이는 CDN이 부팅되기 전일 수 있어 `animate-spin` 같은 유틸리티 애니메이션을 신뢰할 수 없습니다(기존 스피너가 회전하지 않던 원인). 따라서 **오버레이 CSS는 `post-build.js`의 인라인 `<style>`에 둡니다.** 로컬 `npm run dev`용으로 `App.vue`에도 동일 규칙을 두고 양쪽에 동기화 주석을 남겼습니다.
- **활성 회원 자동 동기화 (`activeMembers`)**: `activeMembers`는 `computed` 파생 상태로 `members` 배열을 `enabled` 필드로 실시간 필터링합니다. 따라서 회원 추가 또는 비활성화 시, 대시보드·운동 기록 등 `activeMembers`를 참조하는 모든 뷰가 별도 API 호출 없이 즉시 반영됩니다.

### 3.2. 백엔드 (GAS - Controller-Service)
- **Router (`Api.js`)**: `doGet`(웹앱), `doPost`(챗봇 웹훅) 요청 라우팅 및 공용 로깅 엔진.
*   **Controllers**:
    *   `WebAppController`: 관리자 페이지 전용 API (`google.script.run`).
    *   `KakaoController`: 카카오 챗봇 스킬 전용 JSON 응답 처리.
- **Services**:
  - `MemberService`: 회원 CRUD 및 **스마트 매칭(이모지 제외 이름/이메일)** 지원.
  - `WorkoutService`: 주간 성적 관리 및 **슈퍼패스 월 1회 제한** 비즈니스 룰 강제.
  - `WorkoutLogService`: 개별 상세 운동 기록 및 배치 저장. 저장 시 **주차 범위 검증**과 **주차 카운트 재집계**(`countLogsInRange`) 수행. 주차 번호가 지정되지 않은 주(휴식주간 등)에 대한 저장은 조용히 건너뛰지 않고 명시적으로 거부합니다(`Util.hasWeekNumber`).
  - `WorkoutWeekService`: 주차 일정 관리. 날짜 기준(`getWeekByDate`), 라벨 기준(`getWeek`, 휴식주간 제외), 운동주차 목록(`getWorkoutWeeks`) 조회 제공. 저장은 `batchSaveWeeks`의 **구간 재작성** 방식(3.3 참조).
  - `KakaoService`: 챗봇 시나리오 및 사용자 등록/인증 관리.
  - `MigrationService`: 시트 스키마 자동 관리 및 **날짜/시간 포맷 표준화**.
- **일회성 운영 스크립트 (`DataMigration.js`)**: 레거시 데이터 이관 및 데이터 정합성 복구 스크립트를 모아둔 파일. GAS 편집기에서 직접 실행합니다.
    - `run_recalculateWorkoutCounts(fromDate)`: 실제 로그 기준으로 재계산한 결과를 **로그로만 출력**(Dry-run).
    - `run_applyRecalculatedWorkoutCounts(fromDate)`: 위 결과를 시트에 실제 반영. `count`만 갱신하며 `super_pass`·`note`는 보존하고, 반복 실행해도 결과가 같습니다(멱등).
    - **대상 범위**: `fromDate`(`YYYY-MM-DD`) 이후에 시작하는 주차. 생략하면 **로그가 존재하는 가장 이른 주차의 시작일**이 기준이 됩니다. 그 이전 주차는 로그 없이 이관된 과거 실적(2024/2025)이므로 재계산하면 0으로 밀려버려 제외합니다.
    - **로그가 0건인 주차도 대상에 포함**해야 합니다. 다른 주차 날짜의 로그 때문에 부풀려진 주차는 정작 자기 로그가 0건이므로, 이 행이야말로 0으로 되돌려야 하는 대상입니다.
    - `run_migrateWorkoutWeeksRestFlag()` / `run_applyWorkoutWeeksRestFlagMigration()`: `workout_weeks`를 `is_rest_week` 스키마로 이관(v1.0.5). Dry-run이 기본이며, ① `is_rest_week` 컬럼 추가 ② `start_date` 중복 행 정리(`created_at` 최신 행 유지) ③ 레거시 인코딩(`week_number === 0`)으로부터 플래그 백필 순서로 동작합니다. 빈 셀만 채우므로 반복 실행해도 안전(멱등)하며, **어떤 주차도 재넘버링하지 않으므로 `workout_records`의 기존 조인은 그대로 유지됩니다.** 마지막에 비휴식 주차 간 라벨 충돌을 리포트합니다.
    - `run_importChatHistory()` / `run_applyChatHistoryImport()`: 카카오톡 대화 내보내기에서 복원한 과거 이력(주차·주간기록·운동로그·가입일·리워드)을 시트에 채웁니다(v1.1.0). **채우기 전용(fill-only)**으로, 시트에 이미 있는 값은 절대 덮어쓰지 않습니다. 상세는 3.5 참조.
    - `run_migrateRewardsLogTypes()` / `run_applyRewardsLogTypesMigration()`: `rewards_log.reward_date`를 TEXT→DATE, `amount`를 DOUBLE→CURRENCY로 이관(v1.1.0). 스키마 상수만 바꿔도 기존 시트의 컬럼 타입은 유지되므로, 값 변환과 Table 컬럼 타입 변경을 함께 수행합니다. `2026-Q1`처럼 날짜로 해석할 수 없는 값이나 `미정` 같은 금액이 하나라도 있으면 **아무것도 쓰지 않고** 해당 행을 리포트합니다. 빈 셀은 빈 셀로 유지합니다(미상 금액은 0원이 아니므로). 멱등.
        - typed 컬럼에는 `setNumberFormat()`을 호출할 수 없습니다(`You can't set the number format of cells in a typed column`). 표시 형식은 컬럼 타입이 결정하므로, **타입 변경 → 값 쓰기** 순서로 동작합니다.
    - `run_removeDuplicateWorkoutWeeks()`: **폐기(deprecated)**. `(year, month, week_number)` 기준으로 중복을 판정하는데 이는 주차의 식별자가 아니며, 먼저 나온 행을 남기므로 재넘버링된 주차에서 **올바른 행을 지우고 낡은 행을 남깁니다**. 즉시 return하도록 막아두었습니다.

| `member` | `joined_at`(DATE), `bank_type`(TEXT), `bank_account`(TEXT) 추가 |

### 3.3. 주차 데이터 모델 (`workout_weeks`)

주차 관리의 모든 규칙은 아래 세 가지 원칙에서 파생됩니다.

- **주차의 식별자는 `start_date`입니다.** `year`·`month`·`week_number`는 관리자가 **수동으로 지정하는 라벨**입니다. 시작일이 전월 말일인 주를 다음 달 1주차로 잡거나, 그 달 첫 주를 휴식주간으로 두고 둘째 주를 운동 1주차로 부르는 운영이 가능해야 하므로 자동 계산이 불가능합니다. 따라서 갱신 대상 행을 찾을 때 이 세 컬럼을 절대 사용하지 않습니다.
- **`is_rest_week`가 휴식 여부의 단일 진실입니다.** 과거에는 `week_number = 0`이 휴식주간을 뜻했으나, ⑴ 같은 달의 휴식주간이 모두 `(연, 월, 0)` 하나의 키로 충돌하고 ⑵ JS에서 `0`이 falsy라 `if (weekNumber)` 형태의 가드를 조용히 통과하지 못하며 ⑶ 휴식 해제 시 원래 번호를 복원할 수 없다는 문제가 있었습니다. 휴식주간의 `week_number`는 이제 **보존용 값**(0 = 미지정)이며 조인에 쓰이지 않습니다.
- **`(year, month, week_number)`는 `workout_records`의 조인 키이며, 비휴식 주차 사이에서만 유일해야 합니다.** 기록을 가질 수 있는 집합이 정확히 그 집합이기 때문입니다.

**저장 방식 (`batchSaveWeeks`) — 구간 재작성**

플래너는 한 해 전체를 한 번에 전송하므로, 행 단위 upsert 대신 payload의 `start_date` 최소~최대 구간을 통째로 재구축합니다. 주차 번호를 바꾸면 그 번호 자체가 매칭 키였기 때문에 옛 행이 중복으로 남던 문제(v1.0.3까지)를 구조적으로 제거합니다.

- 재작성 범위는 **`start_date` 기준으로만** 산정합니다. `year`/`month` 컬럼은 관리자 지정값이라 구간 안의 주차가 다른 연·월로 라벨링될 수 있습니다.
- `start_date`가 같은 기존 행에서 `id`와 `created_at`을 승계하여 클라이언트가 들고 있는 주차 참조를 안정적으로 유지합니다. `start_date`가 중복된 행들은 여기서 하나로 합쳐지므로 과거에 생긴 중복이 자동 정리됩니다.
- 구간 **밖** 행은 읽은 값 그대로 되돌려 쓰며 변경되지 않습니다.
- 기록 후에는 항상 `start_date` 오름차순으로 정렬되어 시트가 시간순을 유지합니다.
- 시트 접근은 읽기 1회 + `clearContent` 1회 + `setValues` 1회로, 행마다 `setValue`를 호출하던 이전 방식보다 API 호출이 크게 줄었습니다.

**쓰기 전 검증** — 아래에 해당하면 시트에 손대기 전에 예외를 던지므로 실패해도 데이터가 훼손되지 않습니다.

- payload 내 `start_date` 중복
- 비휴식 주차 간 `(year, month, week_number)` 중복
- 주차 번호가 없는 운동주간
- **고아 행 가드**: 재작성 구간 안에 있으나 payload에 대응 `start_date`가 없는 행(시작일이 월요일 격자에서 벗어난 레거시 행 등). 조용히 삭제하지 않고 해당 날짜를 명시해 저장을 중단합니다.

### 3.4. 테스트 프레임워크
- **모듈형 수동 테스트**: `src/backend/tests/` 내에서 개별 서비스/컨트롤러의 기능을 수동으로 안전하게 검증 (Sandbox 방식).

### 3.5. 대화 이력 복원 (`ChatImportData.js`)

모임 초기 2년치 기록은 시스템 이전이라 카카오톡 대화에만 존재합니다. `scripts/parse-kakao-chat.js`(로컬 Node 스크립트)가 대화 CSV를 파싱해 `src/backend/main/ChatImportData.js`를 생성하고, GAS의 `run_importChatHistory()`가 이를 시트에 반영합니다. CSV 원본은 `migration/`에 두며 gitignore 대상입니다.

**주차·주간기록**
- 주차 식별자는 헤더의 시작일이며, 손으로 적은 헤더가 직전 일요일을 가리키는 경우가 있어 **해당 주의 월요일로 스냅**합니다.
- `(월, 주차)` 라벨은 그 주 게시물들의 다수결로 정합니다(복붙 중 이전 주 라벨이 섞이는 경우가 있음).
- 카운트는 **`(최종)`/`(마감)` 표기 게시물**을 기준으로 합니다. 전체 108주 중 100주에 마감 표기가 있고, 없는 8주는 마지막 게시물로 폴백하며 경고를 남깁니다.
- 시퀀스에 14일 구멍이 있으면 휴식주간으로 채웁니다. 추출된 9개 휴식주가 기존 이관 데이터의 `보너스 휴식 주간` 목록과 정확히 일치했습니다.

**운동 로그**
- 리더보드는 복붙으로 갱신되므로 **어떤 멤버의 숫자가 올라간 게시물 = 인증 1건**이며, 그 게시 시각이 날짜가 됩니다.
- 종류·시간은 증분 전후의 인증 메시지(`헬스 1시간`)에서 가져옵니다. 앞 8시간/뒤 2시간 범위의 (증분, 메시지) 쌍을 시간차 순으로 1:1 배정합니다. 멤버마다 메시지와 리더보드를 올리는 순서가 달라 양방향으로 봐야 하고, 한 운동을 나중에 다시 설명한 메시지가 다른 증분에 붙는 것도 막아야 합니다.
- 표기는 어휘 사전으로 정규화합니다(`트밀`·`런데이`·`○○런`→러닝, `PT`·`웨이트`·`등`·`천국의계단`→헬스, `새태`·`밤테`→테니스, `4.7km`→러닝). `SNPE`·`F45`·`점핑`은 고유 명칭을 유지합니다.
- 근거 메시지가 없으면 `기타(알수없음)` 30분, 종류만 있고 시간이 없으면 그 종류에 30분을 적용합니다. **인증 사진은 사용하지 않습니다** — 텍스트로 읽을 수 있는 정보가 없습니다.
- 시각은 모두 그날 `00:00`입니다. 대화는 인증을 *올린* 시각만 남기고 운동한 시각은 기록하지 않습니다. 일요일 밤 운동이 자정을 넘겨 올라오는 일이 흔하므로 날짜는 **해당 주차 범위로 클램프**합니다.
- **카운트가 최종 진실입니다.** 멤버-주차별 로그 개수를 시트의 `count`에 정확히 맞추며, 부족하면 `기타(알수없음)`로 패딩하고 넘치면 근거가 약한 것(기타 우선, 이후 늦은 날짜순)부터 버립니다. `workout_records.count`는 주차 편집이나 `run_applyRecalculatedWorkoutCounts()` 시 로그로부터 재계산되므로, 개수가 어긋난 로그를 넣으면 나중에 카운트가 조용히 덮어써집니다.

**가입일·리워드**
- 가입일은 카카오톡 초대 시스템 메시지(`서동원 DongWon invited 가은이💕.`)에서 추출합니다. 재가입자는 **최초 초대일**을 사용합니다. 초대 기록이 없는 멤버는 채우지 않습니다.
- 분기 우수 활동자 8건은 발표 문구의 형식이 매번 달라 기계 추출이 불가능하므로 파서 안의 큐레이션 테이블로 관리합니다(생성 파일에 두면 재생성 시 유실). `amount`는 미환급금으로 상품을 구매하는 방식이라 대화에 금액이 전혀 없어 **공란으로 임포트**하며 관리자가 채웁니다.

**임포트 규칙 (fill-only)**
| 대상 | 스킵 판정 |
| --- | --- |
| `workout_weeks` | `start_date` 존재 시 라벨까지 그대로 유지 |
| `workout_records` | `(member_id, year-month-week)` 존재. 조인 라벨은 **시트가 가진 값**을 사용하므로 관리자가 재넘버링한 주차도 그 번호를 따릅니다 |
| `workout_logs` | 해당 주 범위에 그 멤버 로그가 하나라도 있으면 주차 통째로 스킵(중복 카운트 방지) |
| `member.joined_at` | 빈 셀만 채움 |
| `rewards_log` | `(member_id, reward_date)` 존재 |

멤버는 `name`(대화 속 짧은 이름)으로 담고, 임포트가 `member` 시트에서 이모지를 제외한 한글 부분으로 매칭해 실제 `member_id`를 채웁니다. 짧은 이름이 겹치면 잘못 붙는 것을 막기 위해 해당 이름을 건너뛰고 경고합니다. 모든 스크립트는 dry-run이 기본이며 멱등입니다.

## 4. 상세 기능 정의

### 4.1. 카카오 챗봇 (User Interface)
- **사용자 등록**: 챗봇 하단 메뉴를 통해 이메일을 입력하여 시스템 멤버와 카카오 계정 연동.
- **수동 인증**: 사진 없이 버튼 선택만으로 오늘의 운동 종류와 시간을 기록.
- **휴식주간 인증 거부**: 오늘이 휴식주간에 속하면 인증을 받지 않고 기간을 안내합니다. 휴식주간은 기록을 가질 수 없으므로, 예전에는 로그만 남고 주차 카운트는 동기화되지 않아 둘이 어긋나는 문제가 있었습니다.
- **리더보드 공유**: 인증 완료 시 현재 주차의 전체 멤버 성적을 카톡방 복붙용 텍스트로 생성.
- **이미지 인증 (준비 중)**: 타임스탬프 사진 OCR 분석을 통한 자동 기록 기능.

### 4.2. 대시보드 (Admin Dashboard)
- **주차/연도 선택**: 대시보드 상단에서 특정 기간을 선택하여 과거 데이터 및 랭킹 조회.
- **레이블 표준화**: `5-1주차`, `2026 Q2 분기` 등 하이픈 기반의 직관적인 기간 표기.
- **랭킹 및 통계**: 선택한 주차/분기 기준 실시간 랭킹 및 운동 패턴 그래프 제공.
- **주차 랭킹 전원 노출**: 이번 주차 랭킹은 운동 0회인 활동 회원도 포함하여 전체 활동 멤버를 표시(비활성 회원 제외).
- **슈퍼패스 뱃지**: 주차 랭킹에는 해당 주 슈퍼패스 사용자에게 `슈퍼패스` 뱃지를, 분기 누적 랭킹에는 슈퍼패스를 사용한 월별 뱃지(`4월`, `5월` 등)를 이름 옆에 표시.
- **전체 랭킹 확장**: 기본적으로 Top 3 랭킹을 노출하며, 아코디언 버튼을 통해 전체 멤버의 순위로 확장 조회 가능.
- **누적 성적 그래프 전체 선택/해제**: 멤버별 누적 성적 차트에서 범례 개별 토글 외에 전체 시리즈를 한 번에 강조/흐림 처리하는 토글 버튼 제공.
- **화면 간 상태 연동**: 대시보드에서 조회 중인 주차를 유지한 채 운동 기록 탭으로 이동하여 끊김 없는 탐색 지원. 누적 리워드 요약 카드를 클릭하면 리워드 관리 탭으로 이동.

### 4.3. 운동 기록 관리 (Workout Records)
- **이중 검증**: 프론트/백엔드 모두에서 슈퍼패스 중복 사용 및 정책 위반 감지.
- **슈퍼패스 토글 위치**: 목록의 행별 토글과 **운동 기록 모달** 두 곳에서 조작합니다(v1.1.0에서 모달 추가). 모달에서는 주차 메모와 같은 카드에 두어 "이 주차 전체에 대한 설정"임을 드러냅니다. 조작 즉시 서버로 보내는 목록 토글과 달리, 모달 토글은 로그·메모와 함께 저장 시점에 한 번에 반영됩니다.
    - 모달은 위반 조건을 실시간으로 안내하고 토글을 비활성화합니다: 로그 0건이면 `인증 1회 이상부터 사용할 수 있습니다`, 같은 달 다른 주차에서 이미 사용했으면 `M-N주차에 이미 사용했습니다`. 로그 개수는 모달의 로컬 목록(`localLogs`)을 보므로 로그를 추가하는 즉시 조건이 갱신됩니다. **이미 켜져 있는 값은 항상 해제 가능**합니다.
    - `batchSaveWorkoutLogs(..., weeklyNote, superPass)`에서 `superPass`가 `undefined`/`null`이면 시트의 기존 값을 보존합니다. 챗봇 등 이 인자를 모르는 기존 호출 경로가 플래그를 지우지 않도록 하기 위함입니다. 월 1회 규칙의 최종 강제는 기존과 동일하게 `WorkoutService.updateWorkoutCount`가 담당하므로, 클라이언트 검사를 우회해도 서버가 `[슈퍼패스 정책 위반]`으로 거부하고 낙관적 업데이트가 롤백됩니다.
- **요약 바**: `총원 | 환급대상 (목표달성/슈퍼패스) | 미달성` 형식의 압축된 통계 제공. 각 항목은 클릭형 토글 필터로 동작하며(한 번에 하나만 선택), 선택된 항목을 다시 누르면 전체 보기로 해제.
- **연간 주차 셋업**: 기수(연도)별 주차 일정을 일괄 생성 및 관리하는 기능(플래너 모달) 제공.
    - **휴식 토글 무손실**: 휴식으로 지정해도 지정해둔 주차 번호가 보존되어, 해제하면 원래 번호가 그대로 돌아옵니다. 번호가 없던 행(레거시 이관분)에만 같은 달에서 사용되지 않은 가장 작은 번호를 자동 제안합니다.
    - **연도/월은 휴식주간에도 편집 가능**: 대시보드가 `N월 휴식주간`으로 표기하고, 두 달에 걸친 주는 어느 달로 볼지 수동 판단이 필요하므로 주차 번호 입력만 숨깁니다.
    - **중복 사전 차단**: 비휴식 주차 간 `(연, 월, 주차)` 중복이나 번호 누락이 있으면 해당 행을 붉게 표시하고 저장 버튼을 비활성화합니다. 서버도 동일 조건을 재검증합니다.
    - **저장 후 서버 기준 재생성**: 저장 완료 시 주차 목록을 재조회하여 매트릭스를 다시 그리므로, 화면이 로컬 상태가 아닌 실제 저장 결과를 보여줍니다.
- **상태 필터링**: 회원 검색 기능과 함께 환급 대상자, 미달성자 등을 분류하여 조회할 수 있는 필터 제공.
- **휴식주간 지원**: 휴식주간으로 지정된 기간은 화면에 명시적으로 표시되고 기록 입력이 차단됩니다. 분기 성공률·랭킹·리워드 추천의 모집단에서도 제외되어 아무도 점수를 낼 수 없는 주가 분모에 섞이지 않습니다. 이전/다음 주차 이동은 주차 번호가 아닌 실제 달력 상의 시작일(`start_date`)을 기준으로 하여 시간 순서가 꼬이지 않습니다.
- **주차 선택 상태 보정**: 플래너 저장으로 주차 목록이 바뀌면 선택 중이던 주차가 실제로 남아 있는지 확인하고, 사라졌으면 오늘이 속한 주차로 자동 복귀합니다.
- **주차 범위 정합성 보장 (운동 기록 모달)**: 개별 운동 로그는 자신의 `workout_date`가 속한 주차에 귀속되지만 주차 카운트(`workout_records.count`)는 `(year, month, week_number)` 조합으로 저장되므로, 모달에서 선택 주차 밖의 날짜를 입력하면 두 키가 어긋나 로그는 다른 주차에 저장되고 카운트만 현재 주차에 반영되는 문제가 발생합니다. 이를 다음 2중 장치로 차단합니다.
    - **날짜 선택지 제한 (프론트)**: 날짜 필드를 자유 입력(`input[type=date]`)에서 **해당 주차의 날짜만 담은 드롭다운**(`weekDates` computed, `07/22 (수)` 형식)으로 교체. 신규 추가 폼과 목록 내 행 모두 동일하게 적용되므로 범위 밖 날짜는 애초에 표현이 불가능합니다. `min`/`max` 속성은 달력 UI만 제한하고 직접 입력은 막지 못하므로 채택하지 않았습니다.
    - **백엔드 검증**: `batchSaveWorkoutLogs`는 시트 기록 **이전에** 대상 주차의 `start_date ~ end_date` 범위를 벗어난 날짜를 검사하여 `[주차 범위 오류]`로 거부. 구버전 클라이언트나 다른 호출 경로에 대한 최종 방어선입니다. 주차 번호 자체가 없는 경우도 `[주차 지정 오류]`로 함께 거부합니다.
- **가입일 기준 멤버 노출**: 목록·요약 바·대시보드 랭킹은 활성 멤버 전체가 아니라 **해당 주차 종료일까지 가입한 멤버**만 집계합니다(`useStore.membersOfWeek`). 주중 가입자는 그 주부터 포함됩니다. 분기 누적 차트는 주차별로 판정하여 가입 이전 구간을 `null`로 두므로 선이 가입 시점부터 시작합니다(`0`을 넣으면 0회 달성한 것처럼 보임). `joined_at`이 비어 있으면 필터를 통과시킵니다 — 메타데이터 부재를 이유로 실제 기록을 숨기지 않습니다.
- **주차 카운트 자기 복구**: 주차 카운트는 증감(delta) 누적이 아니라 **해당 주차 기간에 실제 존재하는 로그 수**로 산출합니다. 프론트는 모달의 로그 개수를, 백엔드(`countLogsInRange`)는 시트 기록 후 실제 로그를 재집계하여 값을 확정하므로, 이미 어긋난 카운트도 해당 주차를 한 번 저장하면 자동으로 교정됩니다.

### 4.4. 회원 및 리워드 관리
- **회원 필터/검색**: 비활성 회원 포함 여부 토글 및 이름/이메일 기반 검색 기능 제공. 검색 입력창과 CSV 내보내기 버튼은 로직만 존재하고 화면에 노출되지 않았던 것을 v1.1.0에서 연결했습니다.
- **가입일(`joined_at`)**: 기존에는 시스템이 행을 만든 시각(`created_at`)을 가입일로 표시했습니다. 실제 가입일은 이와 다를 수 있으므로 별도 `DATE` 컬럼을 두고 목록·CSV·모달에서 이 값을 사용합니다. 값이 없으면 `created_at`으로 폴백합니다. 모달에서 날짜 선택기로 수정 가능합니다.
- **환급 계좌(`bank_type`, `bank_account`)**: 주간 환급 송금에 쓰는 은행·계좌 정보. 목록에 은행명 배지와 계좌번호를 표시하고 미입력 시 `미등록`으로 표기합니다(이메일도 동일 표기).
    - 계좌번호는 스키마상 TEXT이지만 **UI에서 숫자만 남기고 하이픈·공백을 제거**합니다. 붙여넣기·직접 입력 모두 걸러지고, 저장 시에도 한 번 더 정규화합니다.
    - **은행 자동 추론**: 계좌번호만으로 은행을 판정하는 공식 기준은 없습니다. 은행 식별자는 계좌번호가 아닌 별도의 은행코드(예: 004 국민, 020 우리, 088 신한)이며, 금융결제원 예금주조회 API도 은행을 입력받아야 동작합니다. 시중은행 계좌는 지점·상품 체계에 따라 자리수와 앞자리가 겹치기도 해서(우리 `1002…` / 토스뱅크 `1000…`), 프리픽스를 느슨하게 잡으면 **틀린 은행이 자동 입력되는 쪽이 더 위험**합니다. 그래서 근거가 확실한 두 갈래만 둡니다.
        - **⑴ 문자열 파싱 (주 경로)**: 은행명이 포함된 문자열을 붙여넣으면 별칭 사전으로 은행을 채웁니다. `우리`/`woori`, `KB`/`국민`, `카뱅`/`카카오뱅크`, `toss`/`토스뱅크` 등을 인식합니다. **계좌번호 칸과 은행 칸 양쪽에서** 동작하며, 은행 칸에 `우리 1002-123-456789`처럼 통째로 붙여넣으면 은행과 계좌번호를 한 번에 분리해 채웁니다(숫자 8자리 이상일 때만 계좌로 간주하고, 은행명도 없고 숫자도 부족하면 개입하지 않습니다). 포커스를 벗어날 때 입력된 은행명을 정식 명칭으로 정규화하며(`우리은행`→`우리`), 사전에 없는 은행명은 그대로 보존합니다.
        - **⑵ 프리픽스 추론 (보조)**: 사실상 고정 프리픽스인 인터넷은행 두 곳만 번호로 추론합니다(`3333…` 카카오뱅크, `1000…` 토스뱅크). **나머지 은행은 번호만으로는 추론하지 않습니다.**
        - 두 경로 모두 은행 칸이 비어 있을 때만 채우며 사용자가 언제든 덮어쓸 수 있습니다.
- **리워드 지급일자**: `reward_date`는 기간 라벨(`2026-Q1`)과 날짜(`2026-04-19`)가 섞여 문자열로 정렬되던 것을 `DATE` 타입으로 정리했습니다(v1.1.0). 입력란도 자유 텍스트에서 날짜 선택기로 변경되었으며, 분기 라벨은 `description`에 기록합니다(`2026-Q1 우수 활동자 / 구매상품: …`). `amount`는 `CURRENCY` 타입입니다.
- **리워드 추천 시스템**: 주차별 성적을 분석하여 리워드 지급 대상을 자동으로 추천해주는 기능 지원.
- **리워드 상세/수정 모달**: 리워드 목록 항목을 클릭하면 상세 모달이 열리며, 지급 대상·기간·금액·설명을 수정하거나 해당 내역을 삭제 가능(백엔드 `updateReward` 연동). 금액 입력란은 숫자만 허용하되 화면에는 천 단위 쉼표를 자동 표기하고 서버에는 순수 숫자로 전송.

### 4.5. 시스템 로그 관리
- **로그 조회 및 필터**: 발생 일시, 액션 유형별 내역과 성공/오류 상태 필터링 제공.
- **액션 유형 원본 표기**: 액션 유형은 서버에서 들어온 camelCase 원본 그대로 표시(강제 대문자 변환 제거).
- **상세 데이터 확인**: 로그 클릭 시 JSON 형태의 상세 페이로드를 모달에서 확인 가능.
