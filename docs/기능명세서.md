# 주삼오공 (운동인증방) 관리 시스템 기능 명세서

## 1. 개요
- **목적**: 온라인 운동인증 모임 회원 및 인증현황 관리 및 챗봇 API 서버
- **플랫폼**: Google Workspace (Google Sheets + Google Apps Script).
- **접근 권한**: 나 (관리자)

## 2. 기술 스택
- **FE**: Vue.js 3 (Composition API), Tailwind CSS, Phosphor Icons.
- **BE**: Google Apps Script (GAS).
    - **필수 추가 서비스 (Advanced Services)**: `Google Sheets API`, `GAS JWT lib (1B9l7s2Zx8fQ4cE6H5a1m3Kp9LwJrG2Tt3nXyZAbCdEf)`
- **DB**: Google Sheets.

## 3. 아키텍쳐 & 데이터베이스

### 3.1. 프론트엔드 전략
- SPA (Single Page Application) 형태로 구성.
- 관리자(어드민) 대시보드 및 관리 페이지 위주로 구현. (카카오 챗봇 연동은 추후 별도 분리)

### 3.2. 백엔드 (GAS) 로직
- GAS의 전역 스코프(Global Scope) 특성을 고려하여, 상태 보존이 필요 없는 서비스들은 일반 객체(Plain Object Literal) 방식으로 구현하여 보일러플레이트를 줄이고 간결성을 확보함.
- 컬럼 접근 시 하드코딩된 숫자 인덱스가 아닌 헤더(컬럼명)를 동적으로 찾아 맵핑하는 방식을 사용하여 데이터베이스(시트) 스키마 변경 시의 유지보수성을 높임.
- **주요 서비스 (구현 완료)**:
  - `Util`: 공통 유틸리티 (UUID 생성, 시간 포맷팅, 시트 객체 변환 등)
  - `MigrationService`: 시트 및 컬럼 자동 셋업 (Google Sheets Native Table 기능 활용, 컬럼 타입 강제)
  - `MemberService`: 회원 CRUD (조회, 추가, 수정, 비활성화, 복구)
  - `WorkoutService`: 주간 운동 횟수 Upsert (존재 시 Update, 없을 시 Insert) 및 비고(note) 저장
  - `WorkoutLogService`: 개별 상세 운동 기록 저장 및 조회
  - `RewardService`: 분기/반기별 상금 지급 내역 관리
  - `SystemLogService`: 시스템 로그 및 에러 추적

### 3.3. 데이터베이스 (Google Sheets)
- **공통 원칙**: 
  - 모든 테이블은 Google Sheets의 **'표(Table)'** 기능을 활용하여 생성하며, 각 컬럼에는 엄격한 데이터 타입(BOOLEAN, DOUBLE, DATE_TIME 등)이 지정됨.
  - 모든 테이블은 Soft delete 방식 적용 (실제 삭제 대신 상태값 변경).
  - Google Sheet 특성상 FK(Foreign Key)는 물리적 제약 대신 논리적으로만 연결.

- **`member` 테이블 (회원 관리)**
  - `id`: 내부용 식별자 (UUID)
  - `name`: 닉네임 (카카오톡 오픈채팅방 닉네임과 매핑)
  - `email`: 이메일
  - `created_at`: 생성일시 (ISO 8601)
  - `updated_at`: 수정일시 (ISO 8601)
  - `enabled`: 활성화 여부 (boolean, Soft delete 처리용)

- **`workout_records` 테이블 (주간 운동 횟수 관리 - 정산용)**
  - `id`: 내부용 식별자 (UUID)
  - `member_id`: 회원 ID (논리적 FK -> `member.id`)
  - `year`: 년도 (예: 2026)
  - `month`: 월 (예: 5)
  - `week_number`: 주차 (예: 1)
  - `count`: 해당 주차의 인증 횟수 (integer)
  - `super_pass`: 슈퍼패스 사용 여부 (boolean)
  - `note`: 비고/사유 (예: 부상 이슈, 갓생 이슈 등)
  - `created_at`: 생성일시
  - `updated_at`: 수정일시

- **`workout_logs` 테이블 (상세 개별 운동 인증 기록)**
  - `id`: 내부용 식별자 (UUID)
  - `member_id`: 회원 ID (논리적 FK -> `member.id`)
  - `workout_date`: 운동한 날짜/시간 (YYYY-MM-DD HH:mm)
  - `workout_type`: 운동 종류 (예: 런닝, 걷기, 헬스 등)
  - `duration_minutes`: 운동 시간 (분 단위)
  - `created_at`: 기록 생성일시 (ISO 8601)

- **`rewards_log` 테이블 (분기/반기 상금 지급 내역 기록)**
  - `id`: 내부용 식별자 (UUID)
  - `member_id`: 회원 ID (논리적 FK -> `member.id`)
  - `reward_date`: 상금 지급 기간/일자 (예: '2026-Q1' 또는 '2026-06-30')
  - `amount`: 지급된 상금/상품 금액 (금액 또는 상품명)
  - `description`: 상세 설명 (예: '1분기 최대 달성자')
  - `created_at`: 기록 생성일시 (ISO 8601)

- **`logs` 테이블 (시스템 로그 및 에러 추적)**
  - `id`: 내부용 식별자 (UUID)
  - `timestamp`: 발생 일시
  - `action`: 액션명 또는 요청 유형 (예: `ADD_MEMBER`, `WEBHOOK_ERROR`)
  - `details`: 상세 로그 데이터 (JSON String 등)

## 4. 상세 기능 정의 (관리자 페이지)

### 4.1. 공통 기능 및 헤더 (Header)
- 관리자 인증 및 로그인 처리.
- 전역 네비게이션 (회원 관리, 주차 관리, 리워드 관리 등).

### 4.2. 회원 관리
- **회원 목록 조회**: 등록된 전체 회원 목록(활성/비활성) 및 기본 정보 조회.
- **회원 등록/수정**: 새로운 회원의 정보 입력 및 기존 회원 정보 수정.
- **회원 상태 변경**: 탈퇴 또는 미활동 회원을 Soft delete(`enabled` 상태 변경) 처리.

### 4.3. 주차 및 운동 인증 관리
- **주차(Week) 관리**: 
  - 진행 중인 "년-월-주차" 생성 및 설정.
- **주간 운동 횟수 관리**: 
  - 주차별로 회원들의 운동 인증 횟수를 입력 및 수정.
  - 특이사항(부상 등) 발생 시 비고(note) 컬럼을 통한 사유 기록.

### 4.4. 예치금 및 목표 달성 관리 (회칙 기반)
- **예치금 관리**: 매달 첫째 주 3만원 입금 확인 (중도 참여자 주할 계산 로직 반영).
- **슈퍼패스 관리**: 
  - 회원이 월 1회 한정하여 슈퍼패스 사용 여부 마킹 기능.
  - 한 번 사용 처리된 슈퍼패스는 철회 불가 로직 적용.
- **리워드(상금) 지급 내역 관리**:
  - 분기/반기별 최대 달성자에게 지급한 상금(또는 상품 금액) 및 지급 내역을 별도로 기록하고 조회하는 기능.

## [부록] 주삼오공 회칙 요약

1. **기본 목표**: 주 3회 오운완(오늘 운동 완료) 인증.
2. **예치금 및 환급**:
   - 매달 첫째 주 예치금 30,000원 입금 (중도 참여 주할 계산).
   - 주 3회 달성 시 해당 주 일요일에 7,500원 환급.
3. **리워드 시스템 (분기/반기)**:
   - 미환급금으로 최대 달성자에게 상품 증정.
   - 1인당 연 1회 제한. 중복 1등 시 차순위자에게 상품 지급, 1등은 익월 회비 면제(주 3회 환급은 정상 진행).
4. **인증 기준**:
   - 런닝 30분 이상, 걷기 1시간 이상, 기타 운동은 300kcal 소모 기준 유연하게 적용.
   - '타임스탬프' 앱 사용 필수.
5. **슈퍼패스 제도 (2025년 5월 ~)**:
   - 월 1회 사용 가능. 주 3회 미만(1~2회) 운동 시에도 환급 보장 (0회는 환급 불가).
   - 사용 철회 불가.
